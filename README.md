# Weather Wallpaper

A native macOS live-wallpaper app with a full window **and persistent weather in the menu bar**. A hybrid Metal atmosphere with volumetric clouds, distant cirrus, long branching lightning, restrained sun bloom, rain, snow, fog, and a photographic moon. SwiftUI, AppKit, Metal, Metal Performance Shaders, and Open-Meteo. No third-party code dependencies, video loops, helper processes, analytics, or continuous location tracking.

## Run — no weather account or developer team required

Requires **macOS 14+** and **Xcode 16+** with the Metal toolchain. Xcode 26+ enables the current system Liquid Glass appearance on macOS 26+; older systems retain their native appearance.

1. Open `WeatherWallpaper.xcodeproj`, select the **WeatherWallpaper** scheme, and run. The target uses **Sign to Run Locally** (ad-hoc signing), not an Apple Development certificate. No WeatherKit capability or provisioning profile is needed.
2. Select **Live Weather → Choose City**.
3. Choose **Apply Live Weather**. Alternatively, select a scene and **Apply Scene** without any network connection.

Closing the main window (red close button or ⌘W) hides the Dock icon and keeps the app and wallpaper running in the menu bar. Use **Show Weather Wallpaper** in the menu bar to reopen the window and restore its Dock icon. The menu bar also offers pause/resume animation, resume/remove wallpaper, refresh weather, settings, and quit. **Quit Weather Wallpaper** (⌘Q) stops the app and reveals your original desktop; closing the window is not quitting.

The menu-bar item shows the current weather symbol and temperature, with a clock indicator for stale data. Its native popover includes current conditions, local time, wind, rainfall rate, six upcoming forecast hours, precipitation chances, city selection, source/update information and wallpaper controls. It works even without an applied wallpaper, sharing the existing cache and refresh schedule—no additional renderer, process or polling timer. To use it instead of Apple's Weather menu-bar item, turn off Apple's item in macOS System Settings; the app does not change that system preference for you.

**Open at login** is optional in Settings. Install the app in Applications before enabling it. No launch daemon or separate helper is installed. Existing city, scene, phase and playback preferences remain compatible.

### Command-line build

```sh
xcodebuild -project WeatherWallpaper.xcodeproj -scheme WeatherWallpaper \
  -configuration Release -destination 'generic/platform=macOS' \
  -derivedDataPath DerivedData DEVELOPMENT_TEAM= build
```

App: `DerivedData/Build/Products/Release/Weather Wallpaper.app`.

`CODE_SIGNING_ALLOWED=NO` also works for local compilation and weather previews/live data. Proper Developer ID signing and notarization are still normal requirements for public macOS distribution; they are **not weather-provider authentication requirements**. The previous WeatherKit entitlement, authentication checks and signing-dependent error UI have been removed.

## Weather provider

- **Open-Meteo**, using its public keyless endpoint for eligible **non-commercial use**. Commercial distribution needs an appropriate provider plan / licensed endpoint; see [pricing](https://open-meteo.com/en/pricing) and [terms](https://open-meteo.com/en/terms).
- Data are **model-derived current conditions**, not on-site weather-station observations. The UI calls their timestamp **Valid At**, not Observed.
- Current temperature, WMO condition, cloud cover, precipitation, visibility, and wind drive the sky. The next six forecast hours use the city's local time zone and daytime/nighttime symbols.
- Current precipitation is accumulated over the response's interval (normally 15 minutes). It is explicitly converted to mm/hour; a 15-minute sum is not mistaken for an hourly intensity.
- Requests use explicit Celsius / metres-per-second / millimetre units and UTC Unix timestamps, avoiding ambiguity around daylight-saving transitions. Only seven forecast hours are requested.
- Refreshes occur every 15 minutes, with cached conditions, bounded exponential retry backoff, and a longer delay for HTTP 429. Sleep and inactive user sessions suspend scheduled weather work. **More → Weather Diagnostics** provides provider/status details without exposing coordinates or credentials.
- API data: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), with [Open-Meteo attribution and underlying sources](https://open-meteo.com/en/licence). Attribution appears with weather data, including in the menu bar. The wallpaper is an adaptation of weather data, not a camera view or a provider-endorsed visualization.

Old cached Apple Weather snapshots remain readable and are attributed to the old source until new conditions arrive; they are not silently relabelled as Open-Meteo.

## Visuals and celestial position

### Visual-rebuild status

The default renderer is an **original Weather-inspired interpretation**, not a verified pixel-identical recreation. A user-supplied official Weather screenshot now guides the solar glare treatment; it is a reference, not extracted shipping artwork. The rebuild replaces repeated cloud stamps and independently exposed layers with continuous cloud masses and scene-linear sky/cloud composition. Exact reference matching and final art-direction approval remain a separate visual-review step; passing GPU tests does not establish fidelity to Apple's app.

Recovery checkpoint: clean floating-point opacity, source-aligned cloud lighting, bounded optical-depth shadows and a redesigned small-quad meteor are implemented. The established artistic perspective cloud framing remains the default; a full-azimuth inverse-projection prototype is available only with `WEATHER_WALLPAPER_PANORAMA_REVIEW=1`, because its silhouettes are not visually approved. God rays, catalog stars/constellations, primary/secondary rainbows, ice halos, forecast-informed fronts and full temporal upscaling remain subsequent milestones, **not default features**. A bounded cloud-history review prototype is described below. Existing procedural stars are illustrative, not an accurate catalog sky.

Banding/efficiency follow-up: low-cover integration now uses a 20-step floor instead of 16 and a fully decorrelated per-pixel sample phase instead of the narrow diagonal phase pattern. Cloud RGB and opacity fade together with a quintic falloff from 62% to 84% of screen height, reaching transparent before the hard ray cutoff. This bottom fade is an intentional composition choice. Tests inspect float opacity against a 192-step reference independently of the fade, verify exact zero color/opacity below it, and cover hidden-preview suspension. Local lighting uses half precision to reduce GPU register pressure; density, optical depth and accumulation stay float. Render-pass descriptors are reused without retaining retired drawables, identical scene updates do not wake renderers, and empty star/flare/flash work is skipped. Frame rate and cloud-target resolution are unchanged.

A small per-frame light-depth volume is available for evaluation with `WEATHER_WALLPAPER_LIGHT_CACHE_REVIEW=1`. It applies only to extensive decks, uses less than 1 MiB per renderer, changes lighting but not cloud density, and has no temporal history. It is **off by default**: current paired timings are mixed under competing GPU load, so no blanket utilization/energy improvement is claimed. On/off visual checks compare the cache to the uncached integrator.

### Clouds

The default renderer integrates a bounded **3D cloud layer** into a half-resolution linear HDR target (quarter-resolution in energy-saving mode). A shared, periodic 128³ two-channel shape/erosion texture is generated once on the GPU, not per frame: approximately 4.6 MiB of texels, 6 MiB allocated on the tested M4. Sculpted condensation bases and upper profiles vary with coverage and convection. Bounded two-sample light-path integration estimates optical depth toward the actual source (four at reference sample counts of 96+). Distance haze softens distant banks; separate advected fields form thin, irregular high clouds behind the lower volume.

Rain fills and thickens the cloud volume continuously. Thunderstorms deepen its vertical profile and darken the atmosphere further. Opaque overcast, rain and storm ceilings retain restrained, broad underside shading by reusing existing shape samples—no extra cloud layers or noise fetches. These artistic parameters do not overwrite the provider's reported cloud cover or invent precipitation. Existing six-second transitions blend coverage, thickness and morphology. Integrated transmittance obscures celestial sources and stars, attenuates lightning and controls sun bloom. The full-resolution sky and photographic moon are composited with clouds in linear light before a single sky/cloud exposure shoulder. Cloud drift and wind-driven animation run 35% faster, without changing the displayed wind measurements.

The default uses spatial filtering, not temporal history: no history buffers or reconstruction passes unless the separate review flag below is enabled. Further edge reconstruction and morphology refinements are subject to visual review. The old 1536² atlas and 24-instance path remain available for A/B comparison and allocation fallback; use `WEATHER_WALLPAPER_LEGACY_SKY=1` when launching a development build. Battery mode reduces samples (48 → 20) and cloud resolution, **not** the cloud model.

#### Moonlit notch haze

The former smooth notch halo is replaced by overlapping, gently distorted **silver and blue-grey atmospheric light fields**. A restrained focus near the notch fades into wider, irregular thin mist without a rectangular overlay. Two filtered scales from the existing shared GPU noise volume warp the fields and drift extremely slowly. This is an illustrative nighttime readability aid, not simulated observed mist or a modification to another app's UI; opaque notch-app backgrounds remain opaque. The effect fades away at dawn/twilight, is absent in daytime, and works on displays without a hardware notch.

**Settings → Moonlit notch haze** offers an enable switch, **Compact / Expanded** layout and intensity control (default: Expanded, 75%). Layout and intensity changes ease over 0.65 scene seconds; pause and Reduce Motion snap directly to the chosen layout and freeze atmospheric movement. **Layout selection is manual:** there is no connection to a third-party notch app's expansion state, Accessibility/Screen Recording permission, or polling. Older preferences remain readable and use these defaults without rewriting saved settings.

The effect is desktop-only, independent of the solar Bloom setting, and uses the existing Metal sky composition—not stacked SwiftUI blur layers. A smooth second-derivative feather bounds the work; only the upper-center area samples noise (two lookups). The brightest focus is narrow, with very faint outer wisps. Expanded support ends within the top 24% and central 92% of the display, with intensity tapering well before those mathematical limits. Existing output dithering suppresses gradient banding; the legacy sky adds feathered sub-code-value dither only where mist is present. Two independently wrapped Double-precision texture phases avoid long-uptime motion seams. There is no new texture, render pass, timer, or SwiftUI per-frame animation driver. A separate **32-byte** fragment buffer replaces the former 4-byte glow parameter; main shader uniforms remain **256 bytes**. Cloud/particle quality, frame rates and resolutions are unchanged.

Paired M4 diagnostic medians for the clear-night fixture at 2560×1600 were 0.400 ms off / 0.422 ms former flat halo / 0.431 ms compact mist / 0.442 ms expanded mist; efficient 1600×1000 medians were 0.164 / 0.175 / 0.180 / 0.183 ms. Rain expanded mist measured 1.872 ms normal / 0.338 ms efficient, versus 1.845 / 0.330 ms for the former halo. Transient allocations are unchanged. These are short GPU-only runs, not sustained desktop energy guarantees. Tests check bounded illumination, unchanged daytime/outside pixels, finite and matching hybrid/legacy fields, gentle gradients, low whole-screen light contribution, very slow temporal change and continuity at all four phase wraps. Final appearance on a particular notch app/display still needs user review.

Run `WEATHER_WALLPAPER_MOONLIT_HAZE_REVIEW=<output-directory> MTL_DEBUG_LAYER=1 swift test -c release --filter RenderingTests/testOptionalMoonlitHazeReview` for clear/cloudy/rain captures, real-time 30/15-fps layout-transition clips and GPU diagnostics. `WEATHER_WALLPAPER_REVIEW_STILLS_ONLY=1` skips clips. Optionally set `WEATHER_WALLPAPER_HAZE_BASELINE=<directory>` containing `before-Atmosphere.metal` to compare against the preserved former halo at matching strength.

#### Quality-preserving renderer optimisations

Particle quads (rain, snow, splashes, lens beads and placement guides) now use four-vertex triangle strips rather than six-vertex triangle lists. This removes one third of their vertex invocations without reducing particle counts or changing their shape. Sun visibility samples the same source-position cloud opacity in a dedicated vertex stage and passes a flat value into emission/composition instead of repeating that lookup for every pixel. Widget collision checks skip drops still above every area and candidates that cannot beat an already-found first hit, preserving the original rounded-edge calculations and list ordering. Each renderer caches packed widget bytes until the areas, logical view height, guide or animation permission change.

Cloud sample ceilings, resolutions, frame rates, density, optical effects, passes and GPU texture allocations are unchanged. No cloud-history prototype was enabled. Tested old/new captures and all checked six-second 30/15-fps rain clip frames were **pixel-identical**, including comparison against preserved pre-change shaders. The standard GPU regression allows at most a one-code-value rounding difference for other hardware, with a very small mean-error limit; it covers day/night, rain/storm/sleet/snow/fog, clouds/towers, guides, portrait/landscape and the hour-clock split.

Paired M4 GPU-only median timings (same scene times and quality; reused render target, no screenshot readback in the timed path):

| Fixture | Normal, 2560×1600 | Efficient, 1600×1000 |
| --- | --- | --- |
| Clear day | 0.759 → 0.732 ms | 0.308 → 0.300 ms |
| Rain, 24 areas | 1.862 → 1.764 ms | 0.368 → 0.308 ms |
| Thunderstorm, 24 areas | 1.592 → 1.411 ms | 0.433 → 0.308 ms |

These are workload-specific diagnostics, not a universal speedup or sustained-energy guarantee. Some scenes are neutral or slightly slower: no-widget rain and snow medians increased about 0.7% normal / 2.5% efficient in this run, while means and p95 were mixed. Layout packing rebuilt once rather than 10,000 times in the repeated-input CPU diagnostic, though its absolute cost is small. The tests rotate/reverse variant order with 24 warmup and 72 measured frames, compare individual changes as well as the combined renderer, and preserve the original shader collision function only in test fixtures.

Run `WEATHER_WALLPAPER_OPTIMIZATION_REVIEW=<output-directory> MTL_DEBUG_LAYER=1 swift test -c release --filter RenderingTests/testOptionalQualityPreservingOptimizationReview` for paired captures, timings and clips. `WEATHER_WALLPAPER_REVIEW_STILLS_ONLY=1` skips clips. A portable test-only reference reconstructs the former path; setting `WEATHER_WALLPAPER_OPTIMIZATION_BASELINE=<directory>` instead loads preserved `before-Sky.metal` and `before-Atmosphere.metal` files. This override is test-only.

#### Layered rain, lens droplets and multiple widget areas

In **Settings → Widget rain**, use **Add widget**, **Duplicate**, **Remove**, and the area picker to configure up to **24 rounded areas**. Each has its own enable switch and numeric **X, Y, Width, Height and Corner radius** fields in pixels, with native up/down arrows (1-pixel steps). You can also type decimal values directly. Pixel values refer to the primary display's backing resolution, shown below the controls; X increases rightward and Y downward from the top-left. Saved positions/sizes remain screen-relative and radius remains in logical screen points, so existing layouts are preserved and adapt to other displays. Apply a wallpaper first and enable **Show placement outline** to align the areas with your widgets. The original single-area preference migrates without resetting it. Outlines disappear when Settings closes. There is no automatic detection, dragging or permission prompt. Effects remain behind actual widgets in the wallpaper layer.

Rain now uses interleaved distant/middle/foreground layers with varied speed, size, width, length and opacity. Soft tapered profiles give foreground streaks a short motion trail without image-wide blur. Small coherent lateral movement follows the existing wind clock. At maximum intensity the budget rises from 1,100 to **5,200 drops** (2,600 in energy saver). Fine distant rain remains atmospheric behind widgets; middle/foreground drops meet the first rounded top on their path and become larger ballistic splashes. A capped subset emits three secondary droplets. Higher areas can shield lower ones; these are simple analytic collisions, not fluid simulation.

Up to **140 translucent lens beads** (35 in energy saver) gradually collect, refract the actual rendered background, catch small highlights and occasionally slide downward. Sparse short-lived camera-impact droplets add depth. This needs one reusable full-resolution sRGB scene texture and an additional composition pass **only while wet**, not a fullscreen blur or a per-pixel loop over droplets. The scene texture is released when rain stops, the renderer hides or resources are released. At 2560×1600 it adds approximately 16.5 MB including GPU allocation padding; full rain-fixture transient allocations are about 24.9 MB normal / 7.6 MB efficient at 1600×1000. These are per-renderer diagnostic allocations, not total app memory. Rain/sleet/rainy thunderstorms use the effect; snow and dry storms do not. Pause and Reduce Motion freeze scene animation and suppress widget rebounds and transient camera splashes. Existing cloud sample ceilings, resolutions and frame-rate policies are unchanged.

The supplied Apple Weather screenshot guides the direction, not an exact fidelity claim. Opt-in day/night rain, storm, sleet, placement and star captures, six-second 30/15-fps clips, and GPU diagnostics are available with `WEATHER_WALLPAPER_RAIN_REVIEW=<output-directory> MTL_DEBUG_LAYER=1 swift test -c release --filter RenderingTests/testOptionalLayeredRainAndStarsReview`. Set `WEATHER_WALLPAPER_REVIEW_STILLS_ONLY=1` to skip clips. Timings include test readback and are sensitive to system load; sustained desktop energy and final visual approval remain unverified.

Procedural stars have **55% larger Gaussian footprints**, with mostly near-white sources and restrained orange, pale-blue and occasional reddish temperature variation. Their positions/count, subtle twinkle, cloud/fog concealment and moonlight wash remain unchanged. The retained legacy sky has matching larger, gently tinted stars. This is still an illustrative starfield, not an astronomical catalog.

#### Raised stratocumulus and larger background towers

The former ordinary cumulus look is now **Raised Stratocumulus**. It uses the existing stratocumulus horizontal frequency, bank/sheet styling, erosion and density, while keeping the former cumulus vertical thickness (1.1 artistic world units) and raising its base from 1.15 to 1.55. The separate Stratocumulus preset retains its lower/thinner placement. The old `cumulus` preference key remains compatible and now renders this raised-bank look; no saved preferences need resetting. The same raised profile supplies ordinary partly-cloudy scenes, the generic live fallback and the foreground beneath Towering Cumulus. Reported weather fractions still drive live composition; these are visual profiles, not observed cloud identifications.

Optional background towers are **35% taller** and roughly **31–41% wider** than before. Two stable independent envelope seeds vary depth/spacing, width, opposing lean, shoulder/turret proportions and noise orientation, with slow continuous bounded development—not new random positions every frame. Traversal bounds share the varied geometry, and light/depth normalization handles either tower being tallest. The count stays at two envelopes with the same ray-sample ceilings, target sizes, passes and animation policy. Larger visible volumes can cost more GPU time; in the current M4 fixture, foreground-only→towered means were 4.51→6.29 ms normal and 2.91→3.44 ms efficient. These are feature-on/off readback diagnostics, not an identical-workload speed comparison or sustained-energy guarantee. Some distant tower-edge grain remains.

#### Billow renderer quality refinement (retained)

The preceding cumulus-quality work remains in the renderer for compatible billowing/mixed profiles, but the ordinary foreground now follows the raised stratocumulus profile above. The billow path combines an irregular coherent parent with connected medium-scale lobes, varying top profiles and a flatter condensation-base transition. Its medium billow lookup replaces the former finest erosion lookup in full billowing volumes; fine boundary erosion is filtered and skipped in dense interiors. Broad internal variation follows the billows instead of adding a noisy skin to smooth repeated ovals. All scales share the existing wind transport. Wet/opaque ceilings, continuous sheets and high-only ice are protected; live weather inputs and preview-only tuning separation are unchanged. The historical cumulus-quality review uses an explicit test-only former-cumulus profile so its prior comparisons remain meaningful.

The existing **two** foreground light probes are concentrated nearer the cloud surface to expose local self-shadowing; towers retain their already-short surface-probe spacing. Shaded undersides receive less sky fill, and thin, directly illuminated density receives restrained source-aligned silver lining—not a post-process outline. Close billows lose less contrast to haze, while remote towers blend more into the atmosphere. Pixel- and ray-step-aware mip selection plus a compact, analytically filtered density threshold reduce edge integration noise inside the volume. The full-stratum static sampling remains: no frame-random shimmer, new history, image-wide cloud blur, or sharpening halo. Bilateral image smoothing and alternative jitter experiments were rejected for blur, cost or visible patterning.

Three additional once-built pipeline variants specialize full cumulus, full cumulus with towers, and protected banks. In-between morphology remains continuous through the mixed shader; endpoint specialization does not quantize weather transitions. The **256-byte uniforms, shared noise allocation, render targets/passes, half/quarter resolution, 48/20 sample ceilings, and frame rates are unchanged**. The work adds shading cost, not a free quality upgrade: two M4 isolated runs measured roughly **0.14–0.43 ms extra** normal cumulus cloud-pass time and **0.68–0.81 ms extra** mixed-tower time; efficient tower cost rose about 0.13 ms. Sparse scenes and tail timings remain variable. There is no sustained-energy or universal no-regression claim.

Against each shader's **own** higher-sample (192-step ceiling) field, representative cumulus/sparse/tower edge-opacity RMSE fell about **28–37%** at both quality settings, without changing the sample limits. This is sampling accuracy, not an Apple-reference similarity score or identical geometry comparison; cloud composition/mean opacity changed modestly, and row-bias metrics are not universally improved. Native A/B stills and two six-second motion clips accompany the review. Some fine grain remains on distant and energy-saving edges, especially towers; complete artifact elimination, photographic fidelity and final motion/morphology approval are not established.

#### Condition-aware cloud families

Live requests now include optional **low/mid/high cloud fractions** alongside total cover, using the existing 15-minute schedule. Provider bands are below 3 km, 3–8 km and above 8 km—not universal genus/height boundaries. Current values are preferred; an hourly fallback must be at/before the current condition's valid time, never a future hour. Missing/invalid/stale values remain unknown. Unsupported layer-variable requests fall back to basic weather instead of breaking forecasts; old caches remain readable.

Layer fractions overlap and are not added together. A high-only model sky does not create lower cumulus, an opaque lower deck hides upper patterns, and fog suppresses distant detail. Extensive low cover favors connected banks, middle cover favors finer patches/sheets, drizzle supports a quieter stratus-like base, steady widespread precipitation a thick stratiform profile, and thunderstorms a deeper convective base. Model fields cannot identify every cloud genus: **live shapes are plausible illustrations, not cloud-genus observations**. Missing layer data uses a conservative main layer without automatically decorating clear skies with cirrus.

Scene previews offer **Details → Clouds → Cloud Shape** for compatible named shapes based on the researched WMO families. The former Cumulus entry is now **Raised Stratocumulus**, alongside the original lower Stratocumulus preset; the ten serialized keys remain readable. The same picker also sits under the preview for quick switching. Explicit named shapes remain illustrative. **Clouds → Coverage / Ceiling shading / High veil** sliders tune Scene previews and applied scenes only, never live weather; high veils still hide behind opaque low clouds and fog. Applied preview shapes and tuning are saved compatibly. No automatic lenticular, mammatus, polar-cloud or halo effects are inferred from insufficient data.

**Cloud Development** (below the preview and in Details → Clouds) adds **Towering Cumulus** for Partly Cloudy/Windy scenes and **Developing Thunderstorm** for Thunderstorm scenes. These are development subtypes, not an eleventh genus. Selecting a named Cloud Shape returns to standard development; incompatible selections reset. Applied development scenes persist compatibly with older preferences. Towers supplement ordinary foreground clouds rather than replace them: Towering Cumulus retains the full raised stratocumulus-style foreground, while Developing Thunderstorm keeps a broken foreground base. Live mode never clears its reported lower layer to show the effect.

Live convective development requires fresh shower/thunderstorm codes, usable known low and middle fractions, sufficient cover and visibility. Showers also require reported precipitation; thunder codes can support convection without manufacturing rain. Expired weather, ordinary partly-cloudy weather, high-only cover and unknown lower layers do not activate it. The field blends through existing scene transitions and evolves slowly on a deterministic 15-minute phase, with bounded transport and vertical shear. This is plausible illustration, not detection of congestus or a forecast of storm growth.

Two bounded volumetric tower envelopes combine unequal connected shoulders/turrets with shared cauliflower noise and selective erosion. Bright source-facing billows, self-shadowed interiors and darker bases use the existing illumination model with short surface probes. The same front-to-back integration handles foreground occlusion. Ray/ellipsoid intersections focus the existing capped sample budget on towers; ordinary cloud scenes use a separately specialized shader with tower calculations compiled out. No extra texture, cloud pass, history or polling is added; the optional light-depth grid is disabled for towers. Normal/battery ceilings remain 48/20 samples with the same target sizes and frame rates. Tower rendering does cost GPU time compared with an otherwise empty sky; sustained low-energy operation is not certified by these limits or timing tests.

Cirrus now uses coherently transported patch, curved-feather and broken fine-filament fields with tapered translucent density and footprint-aware mip filtering. A fourth shared-noise lookup is restricted to wisps; cirrostratus veils and cirrocumulus ripples stay distinct. Elevated ice has restrained twilight illumination and moon-dependent night lighting, and remains behind opaque lower cloud/fog. This reuses the existing volume rather than allocating or regenerating a separate filament texture. Visual approval remains open; the result is not photographic or reference-verified.

#### Traversal optimization and cloud-history review

The default skips volume marching on rays missing both tower bounds when no foreground cloud exists. Mixed scenes merge the foreground and tower ray intervals, skip unoccupied gaps, and prioritize the foreground within the same total sample budget. Towers sit farther back, with pixel/step-footprint noise filtering; short surface-light probes are weighted by local tower contribution so ordinary foreground shading is not globally changed. Bounds clip to the density's known condensation base/top; tower heights/inverses are calculated once per frame on the CPU, not with repeated shader sines/divisions. High-only scenes have a specialized shader with volume integration compiled out. Cirrus skips unsupported patch/detail work. Zero-visibility sun emission exits early, while bloom passes are skipped for provably off-screen or fully fog-suppressed sources without suppressing lightning or the visible edge aureole. Frame rates, sample ceilings and cloud-target resolutions are unchanged; normal scenes allocate no new textures. Swift and both shipping Metal uniform layouts now have a **256-byte stride**.

`WEATHER_WALLPAPER_CLOUD_HISTORY_REVIEW=1` enables an **experimental, off-by-default** cloud-only history. This is not a library of interchangeable finished frames: one fresh reduced-resolution cloud image is retained, with an opacity-weighted mean-distance texture for lower clouds. At most one following frame is reconstructed from that fresh image, never from a previously reconstructed image. Motion/depth/opacity edges and uncovered pixels fall back to fresh integration. High-only ice uses its coherent screen-field transport. The final sky, astronomy, precipitation and composition still render at the original frame rate.

Reuse rejects towers, rain/snow/storms/lightning, mixed lower/high layers, panorama mode, reference sample counts, stale/reversed clocks and changed weather/morphology/quality/viewports. Small gradual lighting motion is allowed; a sun/moon source switch is not. Resize, hiding, pause/Reduce Motion, resource release and GPU errors invalidate history. It does not run with the separate light-depth cache. History is capped at **16 MiB per renderer / 32 MiB shared across all displays and preview**, with reservations retained through in-flight GPU completion; allocation/budget failure falls back to fresh rendering. At 2560×1600 on the tested M4, additional history textures allocate about 8.3 MB for ice or 10.5 MB for lower clouds (roughly 2.1/2.7 MB at quarter resolution). These are cache reservations/texture figures, not a cap on total process memory.

Paired review includes full-pipeline timings, isolated cloud passes without readback, native stills, motion clips and a 192-step opacity reference. Two isolated runs measured approximately 9–11% less GPU time for normal towering cumulus and 13–16% less for its efficient path; developing-tower results were smaller/more variable. Ordinary non-convective output in the captured comparisons was byte-identical. Tower opacity error was slightly lower than the pre-change traversal against the reference. History reduced normal overcast/windy **mean full-pipeline** GPU time roughly 14–23% across the review rounds, but cirrus, battery cases and tail latency were mixed. Sampled history frames differed by at most one display code in the normal fixtures (six in the efficient windy fixture). **No blanket utilization/energy claim; history remains opt-in pending sustained energy and broader motion/hardware review.**

To review the cache manually, first quit the existing app yourself, then launch its executable with the flag (do not run a second instance):

```sh
WEATHER_WALLPAPER_CLOUD_HISTORY_REVIEW=1 \
  'DerivedData/Build/Products/Release/Weather Wallpaper.app/Contents/MacOS/Weather Wallpaper'
```

Profiles reuse the same 128³ field and fetched channels, plus selective high-frequency erosion on the main ray probe. There are no extra family-specific targets. A Henyey–Greenstein forward lobe and bounded light optical depth replace the previous screen-derived lighting direction and density-average shadows. Erosion cannot create disconnected material outside the parent shape; distance-dependent noise filtering reduces undersampling. Float cloud buffers contain no added color/opacity dither; a small neutral, sRGB-derivative-scaled dither is applied only at final output. Invisible upper clouds are skipped, density settings are hoisted outside the ray loop, and the main pass represents the dominant visible low/mid/deep layer rather than drawing every possible altitude simultaneously. This is a bounded approximation, not converged physical transport. Visual approval and sustained performance validation remain open.

### Lightning and sun bloom

The sun has two distinct optical regimes, guided by the supplied official Weather screenshots rather than extracted artwork. Clear sky now has a **smaller white-hot core**, controlled radial bloom, pale-yellow rays and amber/orange tips. **Six slender feathered diffraction spikes** rotate slowly **counterclockwise**, one full revolution per 120 scene seconds, while the source and flare trail stay fixed. Pause, suspension and Reduce Motion freeze their shared animation clock. Four more visible soft blue/cyan circular ghosts follow the source–image-center diagonal, with an iridescent purple-blue streak below the source and a broad spectral arc strongest toward the image center. Narrow views scale the optical footprint down and do not wrap the star onto the opposite edge. Live source placement still follows selected-city astronomy; upper-left review framing is illustrative only.

The diffraction profile is 30% shorter with 40% lower overall ray intensity than the first warm-sun version. A further smooth inner attenuation lets the radial bloom dominate the blade roots: ray contribution starts at 40% of that adjusted gain near the center and returns to full gain by optical radius 0.13. Outer tips, feather width, warm color, core/bloom parameters, lens flares and rotation speed are retained.

**Only gloomy weather selects the small, crisp white-disk-only sun:** Overcast, Rain, Snow, Wintry Mix, Thunderstorms and Fog. Clear, Partly Cloudy and Wind keep the bloom, softened rotating spikes, rainbow arc and ghosts even when a light cloud passes over the source; cloud transmission still dims them continuously, and nearly opaque/opaque cloud can hide the source and its effects. Weather-level permission interpolates with scene changes and comes from the condition in both live and preview/applied scenes, not a guessed genus or a single cloudy pixel. Dense visibility haze and manually tuned precipitation also suppress glare. The solar disk radius is unchanged; the moon is now separately enlarged by 50%. Soft rays use the existing quarter/eighth-resolution emission target and single blur; a bounded analytic feather in the existing final composite keeps the thin blades visible through that blur. No extra target/pass, quality downgrade or uniform-layout change was added, but optical shading does have GPU cost. Gloomy conditions skip the unnecessary sun bloom passes without disabling lightning bloom. The existing Bloom and lens effects setting controls all solar optical effects.

Distant broken low/middle clouds now prune weak fragments over a smooth camera-distance range (6–20 world units), using the existing coherent macro field rather than random deletion or a uniform opacity fog. Nearby cloud forms, tower envelopes, wet/opaque ceilings and continuous sheets are protected; provider cover/layer values are not modified. Cirrus/ripples use a gentler horizon/scale proxy for distant patch breakup because their current field is not volumetric. Cirrostratus veils and the requested bottom fade remain intact. In the review fixture, occupied pixels in the horizon band fell about 14% for broken cumulus and 48% for cirrus; nearby opacity and opaque-ceiling opacity were unchanged. These are fixture diagnostics, not inferred cloud distances from weather data.

Each strike generates a seeded **32-segment main channel and three connected forks**, with fewer fine zigzags, thicker cores and tapered energy. Longer strikes reach roughly 90–98% down the wallpaper, visible in open sky near the Dock; no Dock position/accessibility monitoring is needed. The bounded geometry (at most 96 segments) is cached for the strike and drawn as GPU instances, rather than recreated every frame. A short leader progression, subdued return stroke, cloud illumination and native GPU bloom give depth. Frequency and accessibility limits are unchanged. Lightning uses an inexpensive approximate cloud-depth attenuation, not a per-pixel loop over the cloud atlas.

Sun bloom uses an HDR emission target and **MPS Gaussian blur**. It has a quarter-resolution normal path and an eighth-resolution battery / energy-saver path, with matching blur radius; no full-resolution HDR chain is allocated. The soft colored ghosts dim with source transmission and disappear in gloomy weather, behind opaque cloud or with an off-screen sun. Sun occlusion comes from integrated cloud opacity, and lightning samples that same opacity instead of traversing all formations. The existing **Bloom and lens effects** setting controls bloom/flares together; lightning has a separate switch. Reduce Motion / Dim Flashing Lights suppress lightning, as does energy saving.

Golden and blue hours warm/cool the horizon/zenith from existing daylight/twilight; twilight adds a restrained lift to cloud lighting. Rain uses the denser layered system above; snow retains its existing particle path and budget. Nights add phase-driven earthshine on the lunar nightside and illustrative procedural stars. Meteors draw only one small quad during an event, with a shorter tapered orange train that grows from zero, a small luminous head, and equal x/y pixel velocity across aspect ratios. Speed changes duration along the same path rather than stretching that path beyond the screen. Shooting stars can be disabled in Settings or the inspector; they respect daylight, cloud/fog occlusion, pause, suspension and Reduce Motion, independently of the lightning switch. The meteor pass adds no history, frame interpolation or extra targets.

Scene previews include a native **Preview Effects** meteor-shower demo toggle (Details inspector) that switches the preview to a thin night sky; meteor speed is a global setting. Tuning sliders are preview looks only — live weather uses its own data. Both persist compatibly.

### Moon

The existing **2048 × 1024 NASA / LROC photographic map is retained**. In-app quality comes from improved sampling, conservative exposure, visible surface contrast, pixel-sized edge antialiasing, and a tighter halo—not a larger texture or a blurred full-moon cutout. The image is shaded on a sphere for all phases, including the correct illuminated limb and local orientation. Previews expose all eight named phases in the inspector.

Live mode calculates topocentric lunar position and parallax, phase and orientation for the **selected city**, independent of the Mac's time zone. Additional orbital perturbations and approximate atmospheric refraction improve horizon appearance. Sun and moon share a consistent 360° sky projection; motion and rotation take the short path across wrap seams. Ephemerides are computed outside the frame loop and interpolated smoothly between two-minute anchors, refreshed once per minute. A moon above the horizon can appear during daylight; below-horizon and new-moon visibility are suppressed. The inspector shows approximate altitude, azimuth and illumination.

The moon is **50% larger in diameter** than its former size: its apparent radius is now **1.8% of viewport height**, while the sun stays at **1.2%**. Brightness, phase, position and halo settings are unchanged; lunar texture sampling and edge smoothing follow the larger disk in both renderer paths. This is an artistic panorama, **not a calibrated camera or telescope**. Terrain horizons, exact atmospheric conditions, eclipses and lunar libration are not simulated. Geometric lunar positions/illumination are tested against JPL Horizons reference dates. NASA source and usage details are in [`AssetCredits.md`](Sources/WeatherWallpaper/Resources/AssetCredits.md).

## Efficiency and native interface

- One GPU device, queue, pipeline collection and shared cloud field/artwork across displays and the preview. Approximately 30 MiB of shared texture allocations on the tested M4, including retained comparison artwork; not duplicated per display. At 2560×1600, the cloud and bloom targets together allocate roughly 12 MiB in the storm capture on the normal quality path. These are GPU texture figures, not total app-process memory.
- 30 fps normally; 15 fps on battery, under thermal pressure or in Energy Saver. The normal path marches up to 48 steps into a half-resolution cloud target (20 steps at quarter resolution when saving energy); total render resolution scales down with display count and precipitation density adapts. The sun retains inexpensive bloom on battery. Busy GPU frames are skipped rather than blocking the CPU, with at most two frames in flight per renderer.
- Invisible/occluded windows stop rendering and release temporary targets; sleep and inactive sessions suspend animation and weather work. Reduce Motion uses a still frame; critical thermal pressure pauses animation. The menu-bar controls remain available while the app is running, without an always-busy render loop.
- No CPU particle simulation or per-frame cloud asset generation. Lightning geometry changes only at strike onset. Split animation clocks preserve frame precision during long playback.
- Native `NavigationSplitView`, sidebar `List`, toolbar, inspector, searchable city sheet, settings forms, system typography, SF Symbols, and system materials. No forced dark mode, fake glass, custom sidebar chrome or decorative card stack. Light/dark mode and accessibility preferences follow the system.
- The app never changes macOS wallpaper preferences. Removing it or quitting reveals the original desktop. Lock Screen and screen saver are not modified.
- Preferences and one JSON weather cache stay on this Mac. Search goes to Apple Maps; selected coordinates go to Open-Meteo. No data goes to an app-owned server.

Actual GPU time, process memory and energy use depend on hardware, scene and displays. Profile Release builds with Metal System Trace, Time Profiler and Allocations. Offscreen test timings are diagnostics, not battery-life guarantees.
